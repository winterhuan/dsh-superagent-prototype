# 000 理念

[English](000-philosophy.md) | 中文

dsh-superagent 是一个框架，也是一种与 agent（智能体）协作的方式。它的核心原则是：

**尽量少占用人的注意力，尽量多提供价值。**

项目的每一部分都按其占用的注意力来衡量。一条消息、一则通知、一个问题、一项设置、一个面板元素、一段文档都会占用人的注意力，只有提供的价值超过这项成本，才应保留。

## 对 agent 的要求

- **只在收到请求或书面规则允许时行动。** 只有直接向 agent 发出、且来自团队允许的人的请求才有效：此人在允许名单中，或所在对话已被团队开放给任何人提出请求。无人请求的工作必须有团队编写的规则，并从仅记录 agent 原本会做什么的模式开始。
- **只在有人必须操作或能使用结果时发言。** 对请求只确认一次，说明将做什么。工作期间保持安静。结果就绪、需要决定或无法完成时再发言。消息应简短，并发到提出请求的对话中。
- **每次只问一个具体问题，** 并使用结构化形式，让问题直接送达人，而不是埋在长报告中。
- **按影响决定何时停止，而不是按工作量。** 局部改动应做到可供审阅。需要设计决策的改动，应停下来提出明确问题。
- **如实报告。** 草稿标明未完成，失败如实报告，绝不为避免提问而绕过限制。

## 对设计的要求

- **概念少。** 设计只包含来源等领域概念，以及 GitHub、飞书等具体实现。业务需求应成为某个已有概念的属性，或 agent 遵循的提示词，不为它新增概念。
- **设置少。** 某个值适合几乎所有团队时，用默认值替代设置。团队用语言描述的行为应写成提示词，而不是设置。
- **面板只显示需要人的事项。** 优先列出等待人工处理的工作。健康状态不占空间。
- **文档按顺序阅读。** 每篇编号文档只依赖前面的文档，读者无需先了解尚未介绍的概念。

## 责任

agent 使用团队日常接触的账号发表评论、创建 PR（Pull Request）和发送消息。它发出的每条消息都会占用同事的注意力，你对此负责。agent 能做的事情越多，操作者就越需要谨慎对待团队：

- **从小范围开始。** 先使用简短的允许名单，主动工作只做记录。确认 agent 原本会做的事情合理后，再扩大两者的范围。
- **减少噪声。** agent 消息过多时，缩短并收紧提示词，或暂停它。不要再增加消息来解释噪声。
- **不要用它制造数量。** 大量 PR、广播消息和无意义的工作给团队带来的成本超过价值。
- **对它的话负责。** 阅读 agent 以你的名义发布的内容，发现错误时修改提示词。

目标是在恰当的时间提供恰当的帮助，其余时间不打扰。
