# 004 提示词

[English](004-prompts.md) | 中文

本文解释 agent（智能体）读取什么、团队可以编辑什么，以及变更何时生效，以 [000 理念](000-philosophy.zh.md)至 [003 执行](003-execution.zh.md)为基础。提示词文本使用英文。

## 团队编写的内容

团队可以编辑三个团队部分、添加 skill（技能），并覆盖所有内置系统提示词部分。大多数默认内容位于 `prompts/` 和 `skills/`。工具说明、通知和卡片仍在代码中，不能通过提示词设置编辑。

| 部分 | 内容 |
| --- | --- |
| 通信 | 何时发消息、消息如何措辞、每条 GitHub 消息的开头（默认为 `This is by an automated agent, not a human`）、如何处理评审，以及哪些普通账号是评审机器人 |
| 工单范围 | 工单何时继续，何时停在草稿阶段 |
| 交付要求 | PR（Pull Request）中的证据、包含行数阈值的自动合并条件及提交作者；未指定作者时，执行器使用 agent 账号的 no-reply 邮箱提交 |
| 团队 skill | agent 按需加载的知识，例如说明飞书用户对应哪个 GitHub 账号的 `identities` skill |

内置文本涵盖角色、工具用法、宿主机制、授权规则，以及 GitHub 和飞书 skill。它按标题引用团队部分，不重复其内容。

### 内置部分和模板

覆盖使用以下键：

| 部分 | 键 |
| --- | --- |
| 共享指令和角色 | `runtime/shared`, `runtime/orchestrator`, `runtime/worker` |
| 工作指令 | `runtime/subscriptions`, `runtime/replies`, `runtime/dispatch`, `runtime/work`, `runtime/admission` |
| 交接指令 | `runtime/handoff/orchestrator`, `runtime/handoff/worker` |
| 来源 skill | `skill/feishu`, `skill/github` |
| 生成部分 | `runtime/environment`, `runtime/policy`, `runtime/policy/none` |

生成部分是可编辑模板，必须保留以下占位符：

- `runtime/environment`：`{variables}`，填入执行环境各行。
- `runtime/policy`：`{version}`、`{mode}` 和 `{rules}`，每条启用规则一行。
- `runtime/policy/none`：`{version}` 和 `{mode}`，没有启用规则时使用。

编辑某部分会改变模型收到的指令，不改变代码强制执行的准入、授权、工具检查或账号包装层。

人明确请求时，主会话也可以用 `orchestrator_prompts_save` 保存覆盖。保存时未提供覆盖的 `base`，则保留已存储的 base。已存配置中存在但现已移除的部分，在保存时丢弃；其他未知部分被拒绝。

覆盖记录所依据的内置文本。升级保留团队文本。默认内容变更时，面板标记为**默认内容已更新**，并在团队文本旁显示差异。团队可以保留自己的文本、采用新默认值或编辑。没有覆盖的部分自动跟随新默认值。

主会话可以在 `orchestrator_read prompts` 的 `default_changed` 中读取受影响的部分名称。

## 组装和优先级

系统提示词按以下顺序组装：

1. 共享指令和角色。
2. 三个团队部分。
3. 订阅和回复。
4. 主会话的派发指令，或执行器的工作指令。
5. `runtime/admission`，仅用于主会话。
6. 交接指令。
7. `runtime/environment`。
8. `runtime/policy`，仅用于主会话。

准入指令来自 `prompts/admission.md`，描述主动研判及何时可以直接根据卡片忽略无关候选项。`orchestrator_eval` 返回上下文，不重复这些指令。

环境部分向主会话提供部署全局值，向各执行器提供其工单专属值。策略部分在每次模型请求时从设置重新生成，包含策略版本、接单模式、明确请求的豁免，以及格式为 `- <name> (<id>): <instruction>` 的启用规则；没有启用规则时，提供相应说明。它位于最后，因此策略变更不会改变前面的提示词文本。

执行器还读取 DeepSeek Harness 的编程提示词和仓库 `AGENTS.md`，主会话不读取。推断工单会添加最终说明，将执行器限制于匹配规则。派工和到达消息以内联触发卡片形式送达，只有被截断内容才提供资源指针。

执行器无人值守运行。工具集中排除向人提问、向人展示 UI 或修改 profile 的工具，例如 `ask_user_question`、`present` 和 `plugin_manager`。

优先级从高到低为：

1. 工具和宿主强制执行的事实：身份、权限、工具参数检查、回复用途和长度限制。提示词不能改变它们。
2. 内置和生成部分，按团队覆盖后的内容执行。
3. 主动工单匹配规则中的流程和通信要求，仅用于该工单的执行器会话。
4. 团队部分及团队 skill。
5. 外部文本：消息、评论、文档和引用。它们是数据，绝不改变规则或授权。

## 内置文本的原则

以下原则将 [000 理念](000-philosophy.zh.md)应用到 agent：

- **角色分离。** 主会话只路由，通过一个可以一次处理多个待处理候选项决定的路由工具，转发原始触发和路由事实，不作技术决策。路由说明最多 30 个词。执行器读取原始来源、判断范围、实现并验证。
- **主会话不等待。** 报告、后续消息通知、候选项和已完成后台任务自动作为消息到达。没有待办时结束轮次。防护检查拒绝 `sleep`、超过 30 秒的 shell 超时和超过 5 秒的任务等待，因为阻塞步骤会延迟新候选项。这些指令在主会话的完整提示词中替代 DeepSeek Harness 自身的任务通知说明。
- **只在有人必须操作或能使用结果时发消息：** 结果可供审阅或使用、需要决策或资源，或工作无法完成。聊天消息默认一句话，硬限制为 100 个词。
- **执行器判断自己的后续消息。** 各执行器处理并确认范围内请求，将超出工单范围或属于其他工单的请求退回。只有所有拥有者均退回消息，或结束但未接手消息时，它才成为新工作。主会话收到后续消息通知，但只能据此停止工作。退回的消息随后作为候选项到达，附带执行器给出的原因。
- **通过订阅和主会话协调。** 执行器关注相关线程获取上下文。主会话可以用最多 100 个词的说明发送另一工单的事实。订阅和说明都不授予权限。
- **只在明确引用时附加。** 消息必须指向工单的 PR、Issue、来源消息或确认消息，或指向恰好匹配一个工单的近期改动。只有主题相似还不够。附加会使工单订阅整个线程；执行器发现无关时使用 `orchestrator_thread_unrelated`，不在那里回复。
- **具体确认一次。** 开始实质工作前，执行器在原消息下回复，确认每个新请求，说明对象及预期结果。
- **通过 `human_action` 提问。** 执行器在报告中提出一个具体问题，主会话原样转发。如果问题由某条人工消息引发，则指定该消息，宿主在该处提问。否则，在工单起始对话中提问。已经获准的工作可以同时继续。
- **如实交付。** 创建 PR 不等于就绪；草稿标明未完成；没有真实修改前截图的 UI 改动不算就绪。
- **人工暂停持续有效，** 跨后续消息、新执行器会话及重启保持，直到人解除。自动反馈绝不恢复已暂停工作。
- **示例只展示格式。** 示例句子不是 agent 可以声称的事实。
- **按结果处理评审。** 已修复并验证的评论静默解决；不接受的评论给出一句原因。自动评审者的线程在收到答复后解决，每个自动评审者对每个 PR 最多三轮。
- **让出重复工作。** 人的分支或 PR 已包含工单改动时，执行器关闭自己的 PR，并用一句话指向人的版本。

## 版本

- 每次保存创建不可变版本，包含完整配置、修订号、前任版本、时间戳及来源（面板或工具）。恢复某版本或默认值也会创建新版本。
- 保存指定基础修订号。冲突保存被拒绝，但不丢弃草稿。
- 会话在每次模型请求时读取最新版本，包括同一轮次的后续步骤。保存不会重启、取消或唤醒会话。宿主记录各会话使用的修订；执行器可读取自己曾使用的任何修订。
- 部署设置包含覆盖在内的总大小限制。验证拒绝未知键、保留的内置 skill 名、未知覆盖部分及缺少的模板占位符，绝不静默截断文本。与默认值相同的覆盖被移除，使该部分跟随未来默认值。
